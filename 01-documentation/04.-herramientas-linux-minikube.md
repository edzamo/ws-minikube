## Herramientas de monitoreo de recursos

### htop - Monitor interactivo de procesos

**Instalación:**

```sh
sudo apt install htop
```

**Qué hace:** Monitor interactivo de procesos que muestra CPU, memoria y uso de recursos en tiempo real con interfaz visual mejorada que `top`.

**Uso con Minikube:**

```sh
# Monitorear recursos del sistema mientras Minikube está corriendo
htop

# Filtrar procesos relacionados con Minikube/Docker
# Presiona F4 y escribe "minikube" o "docker"
```

**Casos de uso:**
- Verificar consumo de recursos cuando Minikube está ejecutándose
- Identificar procesos que consumen mucha CPU/memoria
- Monitorear contenedores Docker si usas el driver `docker`

**Ejemplo práctico:**

```sh
# 1. Inicia Minikube
minikube start --kubernetes-version=v1.32

# 2. En otra terminal, ejecuta htop
htop

# 3. Busca procesos de Docker/Kubernetes (F4 → escribe "docker")
# Verás procesos como: dockerd, containerd, kubelet, etc.
```

---

### docker stats - Estadísticas de contenedores

**Cuándo usar:** Si Minikube está usando el driver `docker`, puedes monitorear contenedores directamente.

**Comandos útiles:**

```sh
# Ver estadísticas de todos los contenedores en tiempo real
docker stats

# Ver estadísticas de un contenedor específico
docker stats <nombre-contenedor>

# Ver solo contenedores de Minikube
docker stats $(docker ps --filter "name=minikube" --format "{{.Names}}")
```

**Ejemplo de salida:**

```
CONTAINER ID   NAME                    CPU %     MEM USAGE / LIMIT     MEM %     NET I/O     BLOCK I/O
abc123def456   minikube                2.5%      512MiB / 2GiB         25%       1.2MB/800KB  50MB/20MB
```

## Herramientas de procesamiento de datos

### jq - Procesador JSON

**Instalación:**

```sh
sudo apt install jq
```

**Qué hace:** Procesa y formatea datos JSON. Muy útil con `kubectl` que devuelve JSON.

**Uso con Minikube/Kubernetes:**

```sh
# Obtener información de pods en formato JSON y filtrar
kubectl get pods -o json | jq '.items[] | {name: .metadata.name, status: .status.phase}'

# Obtener solo los nombres de los pods
kubectl get pods -o json | jq -r '.items[].metadata.name'

# Ver recursos de un pod específico
kubectl get pod mi-pod -o json | jq '.spec.containers[].resources'

# Contar pods por estado
kubectl get pods -o json | jq '[.items[].status.phase] | group_by(.) | map({status: .[0], count: length})'
```

**Ejemplos prácticos:**

```sh
# Listar todos los servicios con sus IPs
kubectl get services -o json | jq '.items[] | {name: .metadata.name, ip: .spec.clusterIP}'

# Ver eventos de un pod formateados
kubectl get events --field-selector involvedObject.name=mi-pod -o json | jq '.items[] | {time: .firstTimestamp, message: .message}'
```

---

### grep - Búsqueda de texto

**Uso con Minikube:**

```sh
# Buscar en logs de pods
kubectl logs mi-pod | grep "ERROR"

# Buscar en todos los pods
kubectl get pods -o name | xargs -I {} kubectl logs {} | grep "ERROR"

# Filtrar salida de kubectl
kubectl get pods | grep "Running"
kubectl get nodes | grep "Ready"
```

## Herramientas de ejecución repetitiva

### watch - Ejecutar comandos repetidamente

**Instalación:**

```sh
sudo apt install watch
```

**Qué hace:** Ejecuta un comando cada 2 segundos (por defecto) y muestra la salida actualizada.

**Uso con Minikube:**

```sh
# Monitorear pods en tiempo real
watch kubectl get pods

# Monitorear nodos
watch kubectl get nodes

# Monitorear todos los recursos
watch kubectl get all

# Monitorear con intervalo personalizado (cada 5 segundos)
watch -n 5 kubectl get pods

# Monitorear métricas de recursos (requiere metrics-server)
watch kubectl top pods
```

**Ejemplos prácticos:**

```sh
# Monitorear el despliegue de una aplicación
watch kubectl get pods,services,deployments

# Ver logs de un pod en tiempo real mientras se ejecuta
watch -n 1 'kubectl logs mi-pod --tail=20'
```

## Alias - Atajos de comandos

Los **alias** son atajos que permiten crear comandos personalizados o abreviar comandos largos. Son muy útiles para simplificar el trabajo diario con Minikube y Kubernetes.

### ¿Qué es alias?

Un alias es un nombre corto que reemplaza un comando más largo o complejo. En lugar de escribir `minikube kubectl -- get pods`, puedes crear un alias `k` y simplemente escribir `k get pods`.

### Crear alias temporal

Los alias creados en la terminal solo duran mientras la sesión esté abierta:

```sh
# Sintaxis básica
alias nombre-alias='comando-completo'

# Ejemplo: alias para kubectl con Minikube
alias k='minikube kubectl --'

# Ahora puedes usar:
k get pods
k get nodes
k apply -f deployment.yaml
```

### Crear alias permanente

Para que los alias persistan entre sesiones, agrégalos a tu archivo de configuración del shell:

#### Para Bash (`.bashrc` o `.bash_aliases`)

```sh
# Editar el archivo
nano ~/.bashrc
# o
nano ~/.bash_aliases

# Agregar tus alias al final del archivo
alias k='minikube kubectl --'
alias m='minikube'

# Guardar y recargar
source ~/.bashrc
```

#### Para Zsh (`.zshrc`)

```sh
# Editar el archivo
nano ~/.zshrc

# Agregar tus alias
alias k='minikube kubectl --'
alias m='minikube'

# Guardar y recargar
source ~/.zshrc
```

### Ver alias existentes

```sh
# Ver todos los alias definidos
alias

# Ver un alias específico
alias k

# Buscar alias que contengan una palabra
alias | grep kubectl
```

### Eliminar alias

```sh
# Eliminar un alias temporal
unalias nombre-alias

# Ejemplo:
unalias k
```

### Alias avanzados (funciones)

Para comandos más complejos, puedes usar funciones en lugar de alias:

```sh
# Función para obtener logs del último pod
klog() {
  local pod=$(kubectl get pods --sort-by=.metadata.creationTimestamp -o jsonpath="{.items[-1].metadata.name}")
  kubectl logs -f $pod
}

# Función para ejecutar shell en el primer pod de un deployment
kshell() {
  local pod=$(kubectl get pods -l app=$1 -o jsonpath="{.items[0].metadata.name}")
  kubectl exec -it $pod -- /bin/bash
}

# Función para port-forward del primer pod de un servicio
kpf-service() {
  local pod=$(kubectl get pods -l app=$1 -o jsonpath="{.items[0].metadata.name}")
  kubectl port-forward $pod $2:${3:-80}
}

# Uso:
klog                    # Logs del último pod
kshell mi-app           # Shell en pod de mi-app
kpf-service mi-app 8080 # Port forward del servicio mi-app al puerto 8080
```

### Verificar que los alias funcionan

```sh
# Ver todos los alias relacionados con kubectl
alias | grep k

# Probar un alias
k get pods

# Si no funciona, verificar que esté definido
type k
```

### Consejos y mejores prácticas

1. **Nombres cortos pero descriptivos:** `k` para kubectl está bien, pero `kgp` para "get pods" es más claro que solo `gp`.

2. **Documenta tus alias:** Agrega comentarios en tu `.bashrc` explicando qué hace cada alias.

3. **Agrupa por categoría:** Organiza tus alias por secciones (Minikube, kubectl, debugging, etc.).

4. **No abuses:** Demasiados alias pueden confundir. Crea solo los que realmente uses frecuentemente.

5. **Comparte con el equipo:** Si trabajas en equipo, considera crear un archivo de alias compartido.

### Archivo de ejemplo completo

Crea un archivo `~/.minikube_aliases` y agrégalo a tu `.bashrc`:

```sh
# En ~/.bashrc, agrega:
if [ -f ~/.minikube_aliases ]; then
    . ~/.minikube_aliases
fi
```

Contenido de `~/.minikube_aliases`:


## Comandos Docker útiles con Minikube

Si Minikube usa el driver `docker`, estos comandos son útiles:

### Ver contenedores de Minikube

```sh
# Listar todos los contenedores
docker ps

# Listar solo contenedores de Minikube
docker ps --filter "name=minikube"

# Ver contenedores detenidos también
docker ps -a --filter "name=minikube"
```

### Inspeccionar contenedores

```sh
# Ver detalles de un contenedor
docker inspect <container-id>

# Ver logs de un contenedor específico
docker logs <container-id>

# Ver logs en tiempo real
docker logs -f <container-id>
```

### Limpiar recursos Docker

```sh
# Limpiar contenedores detenidos
docker container prune

# Limpiar imágenes no usadas
docker image prune

# Limpiar todo (¡cuidado!)
docker system prune -a
```

## Combinaciones útiles

### Monitoreo completo del clúster

```sh
# Terminal 1: Monitorear pods
watch kubectl get pods

# Terminal 2: Monitorear recursos del sistema
htop

# Terminal 3: Monitorear métricas de Kubernetes
watch kubectl top pods
```

### Debugging con múltiples herramientas

```sh
# Ver estado del pod
kubectl get pod mi-pod -o yaml | grep -A 10 "status:"

# Ver eventos relacionados
kubectl get events --field-selector involvedObject.name=mi-pod

# Ver logs con colores (si tienes ccze instalado)
kubectl logs mi-pod | ccze -A

# Ver recursos del contenedor en Docker (si aplica)
docker stats $(docker ps --filter "name=mi-pod" -q)
```

## Flujo de trabajo recomendado

1. **Iniciar Minikube:**
   ```sh
   minikube start --kubernetes-version=v1.32
   ```

2. **Monitorear en tiempo real:**
   ```sh
   watch kubectl get pods,services,deployments
   ```

3. **Si hay problemas, diagnosticar:**
   ```sh
   # Ver logs
   kubectl logs <pod-name>
   
   # Ver eventos
   kubectl get events --sort-by='.lastTimestamp'
   
   # Ver recursos del sistema
   htop
   ```

4. **Procesar datos si es necesario:**
   ```sh
   kubectl get pods -o json | jq '.items[] | select(.status.phase=="Running")'
   ```
